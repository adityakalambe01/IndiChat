### 9.4 Manual Verification Checklist for Genuinely Blocked iOS Interactions

Because the automated test environment on macOS operates as a headless `CoreSimulator` daemon without an interactive GUI window (`Simulator.app`) or a command-line touch event injection utility (`simctl io` does not support touch taps or drag gestures), the following interactive behaviors must be verified manually on a physical iPhone or GUI Simulator:

#### Checklist:
- [ ] **1. iOS Settings Bottom Scrolling**:
  - Open `IndiChat` on iPhone / GUI Simulator.
  - Navigate to **You -> Appearance & Theme** (and other deep settings pages: Profile, Account, 2FA, Linked Devices).
  - Drag upwards to scroll to the very bottom of the view.
  - **Expected**: ScrollView clearance extends at least 120px above the floating dock; the bottom-most buttons ("Save Changes", "Cancel", "Delete Account") are fully visible and not clipped by the dock or home indicator.
- [ ] **2. iOS Appearance Staging & Save Button Interaction**:
  - Navigate to **You -> Appearance & Theme**.
  - Tap the **Daylight (Light)** mode card.
  - **Expected**: A staged changes action bar slides in at the bottom displaying **"Unsaved Changes"**, a **"Cancel"** button, and a **"Save Changes"** button.
  - Tap **"Save Changes"**.
  - **Expected**: The light theme is persisted to AsyncStorage. Kill and relaunch the app; it must cold-start directly in Daylight mode.
- [ ] **3. iOS Discard Rollback & Cancel Button Interaction**:
  - In Appearance, select an unapplied blur radius (e.g., slide from 20 to 40) or toggle "Reduce Transparency".
  - Tap **"Cancel"**.
  - **Expected**: The staged changes discard immediately, reverting all controls to their previously saved values.
- [ ] **4. iOS Back-Navigation Guard (`useUnsavedChangesGuard`)**:
  - Make an uncommitted change in Appearance (e.g., toggle "Reduced Motion").
  - Attempt to navigate back via top-left back arrow or iOS edge-swipe gesture.
  - **Expected**: Native iOS `Alert.alert` intercepts navigation with "Unsaved Changes" prompt offering "Discard" and "Keep Editing". Tapping "Discard" rolls back state and navigates back. Tapping "Keep Editing" keeps the user on the screen.
- [ ] **5. iOS Camera QR Optical Detection & Passkey Enrollment**:
  - Navigate to **Settings -> Link a Device**.
  - Point camera at web pairing QR code.
  - **Expected**: Camera scanner recognizes the QR code payload and pairs the device.
  - Navigate to **Settings -> Passkeys -> Create a Passkey**.
  - **Expected**: Native iOS FaceID/TouchID prompt appears to enroll WebAuthn credential.

### 9.5 Remaining Technical Limitations Documented
1. **Headless CoreSimulator CLI Input Boundaries**:
   - `xcrun simctl` provides robust process lifecycle control (`launch`, `terminate`, `openurl`), UI appearance switching (`simctl ui appearance`), and screen capture (`simctl io screenshot`), but contains **no touch injection or drag/swipe CLI tooling**.
   - As a consequence, bottom-extent scrolling and touch button taps on iOS were not inferred from Android and are explicitly documented as **Unverified (Touch input blocked in headless CLI)**.
2. **Edge-Sharpness Interpretation**:
   - Sobel edge-sharpness and pixel variance measurements were evaluated strictly as supporting empirical evidence on identical background regions excluding changing labels or controls. They confirm the visual diffusion effect across blur states (Level 0 vs 40 vs Reduced Transparency).
3. **Preservation Invariant**:
   - The reference preview [`preview/preview-liquid-glass.html`](file:///Users/innodaredevil/Desktop/IndiChat/preview/preview-liquid-glass.html) and all backend/shared contracts remain preserved. No git commits, pushes, or deployments were executed.
