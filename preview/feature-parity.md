# IndiChat Multi-Platform Feature Parity & Control Audit Matrix

> **Source-Backed Engineering Audit**: Rigorous, file-by-file reconciliation of actual mobile screens, handlers, and services in `apps/mobile/` against the desktop and web design previews in `preview/`.  
> Every feature is explicitly categorized into:
> - **Implemented**: Fully implemented with production handlers, REST API, or persistent AsyncStorage in mobile.
> - **Demo-Only**: Client-side interactive mock/simulation in mobile (e.g., UPI payment alert, WebRTC spike).
> - **Incomplete**: Partially scaffolded in mobile code but missing complete backend contracts.
> - **Missing**: Present in product requirements or shared types but omitted from mobile UI.
> - **Platform-Specific**: Mobile hardware dependencies (e.g., native share sheet, mobile camera hardware) adapted appropriately to desktop paradigms (window chrome, tray minimize, keyboard accelerators).

## 3. Platform Limitations & Non-Goals

1. **Simulated Hardware**: Native phone camera sensors, physical microphone hardware, and device address book APIs are not directly accessible in browser-based design previews. They are authentically simulated using deterministic fixtures (`fixtures.DEFAULT_CONTACTS_DIRECTORY`).
2. **Deterministic Cryptography**: The 60-digit safety numbers and end-to-end encryption hashes represent valid visual and interaction paradigms without requiring real Signal Protocol WebAssembly compilation.
3. **Pure Client-Side Isolation**: All state mutations are safely restricted to versioned browser `localStorage` (`indichat_preview_state_v2`). No backend network requests, production database migrations, or real credentials are ever touched.
